Node.js Modules
Built-in · Custom · ESM vs CommonJS
ESM vs CommonJS — Two Module Systems
Node.js supports two ways to share code between files. SatyaCheck uses ESM (ECMAScript Modules) — the modern standard.
Feature CommonJS (old) ESM — Used in SatyaCheck ✅
Syntax to import const x = require('./file') import x from './file.js'
Syntax to export module.exports = x export default x or export { x }
Declared in package.json "type": "commonjs" (default) "type": "module"
File extension .js or .cjs .js or .mjs
Top-level await ❌ Not supported ✅ Supported

Built-in Module: fs (File System)
Used to read and write files on disk. SatyaCheck uses it to save user data and analysis results as JSON files when a database is not connected.
📄 artifacts/api-server/src/routes/auth.js — fs module usage 
import fs   from "node:fs";    // Built-in file system module
import path from "node:path";  // Built-in path module

// The file path where users will be stored
const USERS_FILE = path.resolve(process.cwd(), "users-storage.json");

// READ: Load all users from file
function loadUsers() {
  if (fs.existsSync(USERS_FILE)) {
    return JSON.parse(fs.readFileSync(USERS_FILE, "utf-8"));
  }
  return [];
}

// WRITE: Save users back to file
function saveUsers(users) {
  fs.writeFileSync(USERS_FILE, JSON.stringify(users, null, 2), "utf-8");
}
Built-in Module: crypto
Used for security operations like hashing passwords so they are never stored in plain text.
📄 auth.js — crypto for password hashing 
import crypto from "node:crypto";

// Hash a password — never store plain text passwords!
function hashPassword(password) {
  const salt = crypto.randomBytes(16).toString("hex");
  const key  = crypto.scryptSync(password, salt, 64);
  return `${salt}:${key.toString("hex")}`;
}
// Result stored in DB: "a3f5c8...abc123:def456..."  — unreadable by humans!

// Also generates secure random session tokens
const token = crypto.randomBytes(32).toString("hex");

How the browser talks to the server
What is HTTP?
HTTP is the language the browser (client) uses to communicate with the server. Every time you open a website or submit a form, an HTTP request is made.

(Client)
──── HTTP Request ────→
🗄️ Node.js Server
(Our Backend)

📦 Data / HTML / JSON
Basic HTTP Server using Node's Built-in http module
This is the simplest possible server — no Express yet. Pure Node.js.
📄 Concept — raw http module (not in project, but taught in syllabus) 
import http from "http";

const server = http.createServer((req, res) => {
  // req = the incoming request from browser
  // res = what we send back

  if (req.method === "GET" && req.url === "/") {
    res.writeHead(200, { "Content-Type": "text/html" });
    res.end("<h1>Hello from SatyaCheck!</h1>");
  } else {
    res.writeHead(404);
    res.end("Not Found");
  }
});

server.listen(3000, () => console.log("Server on port 3000"));
⚠️
Why not use raw http in our project? The raw http module is powerful but very low-level — you have to manually handle every URL. In SatyaCheck, we use Express which wraps http and gives us clean, organized routing. Express is built on top of http internally.

Express App Setup & Middleware
Middleware = functions that run on EVERY request before it reaches the route handler. Think of it like airport security — every passenger goes through it.
📄 artifacts/api-server/src/app.js — full Express setup 
import express   from "express";
import cors      from "cors";
import pinoHttp  from "pino-http";
import path      from "path";
import router    from "./routes/index.js";

const app = express();  // Create the app

// ── MIDDLEWARE (runs on every request) ────────────────
app.use(cors());                          // Allow cross-origin requests
app.use(express.json({ limit: "50mb" }));  // Parse JSON request bodies
app.use(express.urlencoded({ extended: true })); // Parse form data
app.use(pinoHttp({ logger }));           // Log every request

// ── API ROUTES ────────────────────────────────────────
app.use("/api", router);  // All routes start with /api

// ── STATIC FILE SERVING (PRODUCTION ONLY) ────────────
if (process.env.NODE_ENV === "production") {
  const staticPath = path.join(__dirname, "../frontend-js/dist");
  app.use(express.static(staticPath));  // Serve HTML, CSS, JS files

  // ── SPLAT / FALLBACK ROUTE ── send index.html for all non-API paths
  app.get(/^(?!\/api).*/, (_req, res) => {
    res.sendFile(path.join(staticPath, "index.html"));
  });
}

export default app;
✅
What is the Splat/Fallback Route? The regex /^(?!\/api).*/ means: "match ANY path that does NOT start with /api". This is the SPA (Single Page Application) fallback — it sends React's index.html for every unknown route so React Router can handle the navigation on the client side.

Dynamic Routing — URL Parameters
Dynamic routes use :param in the URL. The value after the colon is extracted from the URL.
📄 Concept of Dynamic Routes (used in auth.js pattern) 
const router = Router();

// Static route — exact URL match
router.get("/users", (req, res) => {
  res.json({ message: "All users" });
});

// Dynamic route — :id is a URL parameter
router.get("/users/:id", (req, res) => {
  const userId = req.params.id;  // Extracted from URL
  // GET /api/users/42  →  userId = "42"
  // GET /api/users/abc →  userId = "abc"
  res.json({ userId });
});

// Multiple dynamic segments
router.get("/users/:id/posts/:postId", (req, res) => {
  const { id, postId } = req.params;
  res.json({ id, postId });
});

// Query string parameters (?key=value)
router.get("/search", (req, res) => {
  const q = req.query.q;  // GET /api/search?q=fake+news
  res.json({ query: q });
});

Register Endpoint — POST /api/auth/register
📄 artifacts/api-server/src/routes/auth.js 
router.post("/auth/register", (req, res) => {
  const { name, email, password } = req.body; // Data from form/frontend

  // 1. Validate input
  if (!name || !email || !password) {
    return res.status(400).json({ message: "All fields are required." });
  }
  if (password.length < 6) {
    return res.status(400).json({ message: "Password min 6 characters." });
  }

  // 2. Check if email already registered
  const users = loadUsers();
  const exists = users.find(u => u.email === email);
  if (exists) {
    return res.status(409).json({ message: "Email already registered." });
  }

  // 3. Hash the password (NEVER store plain text)
  const passwordHash = hashPassword(password);

  // 4. Create and save the new user
  const newUser = {
    id: `usr_${Date.now()}`,
    name, email, passwordHash,
    token: crypto.randomBytes(32).toString("hex"),
    createdAt: new Date().toISOString(),
  };
  users.unshift(newUser);
  saveUsers(users);

  // 5. Return success (without the passwordHash!)
  const { passwordHash: _, ...safeUser } = newUser;
  return res.status(201).json({
    success: true,
    user: safeUser,
    token: newUser.token,
  });
});
Protecting Routes with Auth Middleware
📄 auth.js — GET /api/auth/me — validates token 
router.get("/auth/me", (req, res) => {
  // Browser sends: Authorization: Bearer <token>
  const authHeader = req.headers.authorization;

  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    return res.status(401).json({ message: "Unauthorized" });
  }

  const token = authHeader.replace("Bearer ", "");
  const users = loadUsers();
  const user  = users.find(u => u.token === token);

  if (!user) {
    return res.status(401).json({ message: "Invalid token" });
  }

  return res.json({ user: sanitizeUser(user) });
});

CORS — Cross-Origin Resource Sharing
By default, browsers block requests from one domain to another (security feature). CORS tells the browser: "It's OK — this server allows requests from the frontend."
⚠️
The Problem Without CORS: Frontend runs on http://localhost:5173 — Backend runs on http://localhost:3000. These are different "origins". Without CORS, the browser blocks all API calls and you get: Access to fetch at '...' has been blocked by CORS policy
📄 app.js — CORS setup 
import cors from "cors";

// Simple: allow ALL origins (fine for development)
app.use(cors());

// Production: only allow your specific frontend URL
app.use(cors({
  origin: ["http://localhost:5173", "https://satyacheck.vercel.app"],
  methods: ["GET", "POST", "PUT", "DELETE"],
  credentials: true,  // Allow cookies/auth headers
}));
📄 frontend-js/vite.config.js — Vite Proxy (alternative to CORS in dev) 
// In development, Vite acts as a proxy.
// Any /api call from the browser goes through Vite → backend.
// This means SAME origin, so no CORS needed in dev!
server: {
  proxy: {
    "/api": {
      target: "http://localhost:3000",  // Forward to Express
      changeOrigin: true,
    },
  },
},
Multer — File Upload Middleware
Multer handles multipart/form-data — the format used to upload files (images, PDFs, etc.) from HTML forms or the frontend.
📄 Concept — how Multer works (ready to add to SatyaCheck for image analysis) 
import multer from "multer";   // npm install multer

// Configure where and how files are stored
const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, "uploads/"),
  filename:    (req, file, cb) => cb(null, `${Date.now()}_${file.originalname}`),
});

const upload = multer({
  storage,
  limits: { fileSize: 10 * 1024 * 1024 },  // 10 MB max
});

// Route that accepts a file upload
// "image" matches the field name in the form
router.post("/analyze/image", upload.single("image"), (req, res) => {
  const file = req.file;   // The uploaded file info
  const body = req.body;   // Other form fields

  // file.path = where it was saved on disk
  // file.mimetype = "image/jpeg" etc.
  res.json({ saved: file.path });
});
