1. Executive Summary & Scope

The Database Architect is responsible for data persistence, schema integrity, and storage resiliency in the SatyaCheck verification platform. The role designs relational models capable of storing complex forensic news analyses, multi-turn conversational transcripts, and statistical aggregate metrics, while providing a zero-downtime dual-persistence fallback strategy.

Core Engineering Objectives:
  • Design normalized, high-performance relational schemas using Drizzle ORM in pure JavaScript (ES Modules).
  • Implement hybrid relational-document storage utilizing PostgreSQL JSONB and native array types for nested forensic data.
  • Build a Dual-Persistence Engine: Primary storage routes to PostgreSQL; if the database is unavailable, writes failover seamlessly to an atomic local JSON document store (analyses-storage.json) without throwing 500 errors.
  • Formulate optimized SQL aggregation queries (unnest, group-by, windowing) for dashboard analytics and trending topics.
  • Manage automated schema migrations and validation boundaries with Drizzle Kit and Drizzle Zod.

4. Core Code Implementations

4.1 Database Connection Pool & Client Export (lib/db/src/index.js)

import { drizzle } from "drizzle-orm/node-postgres";
import pg from "pg";
import * as schema from "./schema/index.js";

const { Pool } = pg;

// Initialize connection pool only when DATABASE_URL environment variable is provided
export const pool = process.env.DATABASE_URL
  ? new Pool({ connectionString: process.env.DATABASE_URL })
  : null;

// Export initialized Drizzle instance or null for graceful offline fallback
export const db = pool ? drizzle(pool, { schema }) : null;

export * from "./schema/index.js";

4.2 Relational Drizzle Schema Definition (lib/db/src/schema/analyses.js)

import { pgTable, text, serial, integer, timestamp, jsonb } from "drizzle-orm/pg-core";
import { createInsertSchema } from "drizzle-zod";

export const analyses = pgTable("analyses", {
  id: serial("id").primaryKey(),
  content: text("content").notNull(),
  sourceType: text("source_type").notNull(),
  prediction: text("prediction").notNull(),
  confidence: integer("confidence").notNull(),
  explanation: text("explanation").notNull(),
  keywords: text("keywords").array(),
  detectedSource: jsonb("detected_source"),
  additionalSources: jsonb("additional_sources"),
  mediaType: text("media_type").default("text"),
  geminiVerification: jsonb("gemini_verification").default(null),
  factBreakdown: jsonb("fact_breakdown").default(null),
  createdAt: timestamp("created_at").defaultNow(),
});

export const analysisResults = pgTable("analysis_results", {
  id: serial("id").primaryKey(),
  analysisId: integer("analysis_id").notNull(),
  verifiedArticles: jsonb("verified_articles").default([]),
});

export const insertAnalysisSchema = createInsertSchema(analyses).omit({
  id: true,
  createdAt: true,
});

const trending = await db.execute(sql`

  FROM analyses

5. Dual-Persistence Resiliency Strategy

A core strength of the SatyaCheck architecture is that database network dropouts, credential rotation delays, or local offline evaluation never prevent the user from completing fact-checks. The system implements a robust Failover Storage Handler: 

const STORAGE_FILE = path.resolve(process.cwd(), "analyses-storage.json");

function loadLocalAnalyses() {
  try {
    if (fs.existsSync(STORAGE_FILE)) {
      return JSON.parse(fs.readFileSync(STORAGE_FILE, "utf-8"));
    }
  } catch {}
  return [];
}

function saveLocalAnalysis(entry) {
  try {
    const list = loadLocalAnalyses();
    list.unshift(entry);
    // Persist latest 100 entries atomically
    fs.writeFileSync(STORAGE_FILE, JSON.stringify(list.slice(0, 100), null, 2), "utf-8");
  } catch (err) {
    console.error("Local storage write error:", err);
  }
}

6. PostgreSQL vs. MongoDB Comparison

Evaluation Criterion PostgreSQL + Drizzle ORM (Selected) MongoDB / NoSQL Alternative
Data Consistency Strict ACID guarantees across relational chat & analysis tables. BASE / Eventual consistency; lacks native multi-table constraints.
Structured + JSON Hybrid Native JSONB enables indexed JSON querying alongside relational keys. All data stored as BSON; lacks native relational foreign keys.
Resource Footprint Lightweight connection pool; zero memory leaks with pure JS driver. Heavy mongod daemon, elevated RAM overhead for index caches.
Analytical Queries Fast native SQL GROUP BY, unnest(), and window functions. Requires complex aggregation pipelines with higher compute cost.

7. Viva & Technical Defense Q&A

Q1: Why did you choose Drizzle ORM over Prisma?
A: Prisma relies on an external Rust binary query engine (over 40MB) which adds cold-start latency and compilation friction. Drizzle is a lightweight, zero-dependency SQL query builder written in pure JavaScript that generates clean SQL matching native queries, running effortlessly in ES Modules.
Q2: Why did you use PostgreSQL instead of MongoDB?
A: SatyaCheck requires relational integrity between conversations and messages (cascade deletes), as well as complex analytical aggregations on keywords and prediction counts. PostgreSQL's native JSONB type gives us the exact flexibility of MongoDB documents while preserving strict foreign key constraints and ACID safety.
Q3: How does the system behave if the PostgreSQL database goes down?
A: The application uses a defensive dual-mode architecture. When DATABASE_URL is absent or the connection throws an exception, all read and write queries automatically redirect to analyses-storage.json. The frontend UI continues functioning without throwing HTTP 500 errors.
