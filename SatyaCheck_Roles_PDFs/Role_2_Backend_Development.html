1. Executive Summary & Scope

The Backend Developer designs, builds, and maintains the server-side infrastructure of SatyaCheck. This role functions as the central operational bridge connecting the client-side user interface (Role 1), the relational/file persistence database layer (Role 3), and the artificial intelligence verification runtime (Role 4).

Core Engineering Objectives:
  • Architect a pure JavaScript, native ES Module HTTP server on Express 5 without compilation overhead.
  • Enforce strict request boundary limits (50MB body limit for base64 image transfers, CORS whitelist).
  • Build a real-time Server-Sent Events (SSE) streaming endpoint (/api/chat) for token-by-token AI answers.
  • Implement defensive error handling so third-party failures or database dropouts never result in unhandled 500 crashes.
  • Provide high-throughput structured JSON logging using pino and pino-http.

4. Core Code Implementations

4.1 Server Bootstrapper & Error Lifecycle (src/index.js)

import app from "./app.js";
import { logger } from "./lib/logger.js";

const port = Number(process.env.PORT || 3000);

if (Number.isNaN(port) || port <= 0) {
  throw new Error(`Invalid PORT value: "${process.env.PORT}"`);
}

const server = app.listen(port, (err) => {
  if (err) {
    logger.error({ err }, "Fatal error listening on port");
    process.exit(1);
  }
  logger.info({ port }, "SatyaCheck Backend Server listening successfully");
});

// Graceful process termination
process.on("SIGTERM", () => {
  logger.info("SIGTERM signal received. Closing HTTP server gracefully.");
  server.close(() => process.exit(0));
});

4.2 Application Configuration & Middleware (src/app.js)

import express from "express";
import cors from "cors";
import pinoHttp from "pino-http";
import path from "path";
import { fileURLToPath } from "url";
import router from "./routes/index.js";
import { logger } from "./lib/logger.js";

const app = express();

// High-speed structured logging
app.use(pinoHttp({
  logger,
  serializers: {
    req: (req) => ({ id: req.id, method: req.method, url: req.url?.split("?")[0] }),
    res: (res) => ({ statusCode: res.statusCode })
  }
}));

app.use(cors());
app.use(express.json({ limit: "50mb" })); // Accommodates high-res image uploads
app.use(express.urlencoded({ extended: true, limit: "50mb" }));

// Mount all API endpoints under /api
app.use("/api", router);

export default app;

4.3 Real-Time Server-Sent Events (SSE) Streaming (src/routes/chat.js)

router.post("/chat", async (req, res) => {
  const { messages: rawMessages } = req.body;
  if (!rawMessages || !Array.isArray(rawMessages)) {
    return res.status(400).json({ message: "messages array is required" });
  }

  // Set HTTP headers for persistent Server-Sent Events stream
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");
  res.setHeader("Access-Control-Allow-Origin", "*");

  try {
    const stream = await ollama.chat.completions.create({
      model: process.env.OLLAMA_MODEL || "llama3.2:1b",
      messages: rawMessages,
      stream: true,
    });

    for await (const chunk of stream) {
      const token = chunk.choices[0]?.delta?.content || "";
      if (token) {
        res.write(`data: ${JSON.stringify({ type: "content", content: token })}\n\n`);
      }
    }
    res.write(`data: ${JSON.stringify({ type: "done" })}\n\n`);
    res.end();
  } catch (err) {
    req.log?.error({ err }, "SSE streaming failed");
    res.write(`data: ${JSON.stringify({ type: "error", error: "Streaming failed" })}\n\n`);
    res.end();
  }
});

5. Architectural Resilience & Fault Tolerance

  • Database Decoupling: The backend never allows database network timeouts to crash an analysis. If PostgreSQL is unreachable, analysis results are immediately captured in a local append-only JSON file (analyses-storage.json).
  • Memory & Timeout Caps: Web scraping requests (via AbortController) time out after strictly 10 seconds to prevent denial-of-service hanging from slow remote target websites.
  • Payload Sanitization: Request bodies are strictly validated before being passed to AI prompts, mitigating prompt injection vulnerabilities.

6. Viva & Technical Defense Q&A

Q1: Why did you choose Server-Sent Events (SSE) instead of WebSockets for the AI chat?
A: The AI assistant is unidirectional (the client sends a message once, and the server streams tokens back). SSE runs over standard HTTP/1.1 without complex WebSocket handshakes, supports automatic browser reconnection natively, and bypasses corporate proxy firewalls seamlessly.
Q2: Why did you remove TypeScript from the backend and use native ES Modules?
A: Pure Node.js ES Modules run natively with node src/index.js. This eliminates the build step (no esbuild, tsc, or watcher required), reduces memory consumption, and speeds up local developer reboot cycles to under 500ms.
Q3: How does the backend prevent Out-Of-Memory (OOM) errors during image verification?
A: Express body parsers enforce a strict 50mb cap, and images are processed as Base64 payloads directly passed to the vision pipeline without being stored as temporary clutter on disk.
